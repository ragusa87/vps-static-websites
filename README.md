# vps-static-websites

Source of truth for the static websites hosted on the VPS.

Each top-level folder is a self-contained application. **The folder name is the
URL (hostname) it is served from**, and its `index.html` is the entry point.
Everything inside a folder is served statically as-is — no build step, no
framework.

## How it is served

- A single shared **Caddy** container (`compose.yaml` + `Caddyfile`) serves
  every site. The document root is resolved from the `Host` header, so a
  request for `foo.constantin.dev` is served from `/srv/foo.constantin.dev/`.
- **Traefik** terminates TLS and routes traffic. It only routes the hosts it
  knows about; that list is generated by `upgrade.sh` from the folders present
  here, so the generated config doubles as the host whitelist.
- `upgrade.sh` scans the folders and (re)generates the Traefik file-provider
  config. It runs automatically on deploy.

## Adding a site

Create a new folder named after the hostname, drop an `index.html` inside, and
push. See the **"how to add a new learning website"** skill for the full
procedure.
